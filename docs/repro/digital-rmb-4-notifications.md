# 复现样本：数字人民币支付触发的 4 条通知

**来源**：用户真机截图（2026-10-01 11:23–11:24）
**现象**：一笔 **17.45 元**的京东消费（走数字人民币），触发了 **4 条**通知，
但 App 只记成 **2 条**流水（锁屏上有两条「已自动记一笔账 · ¥17.45」）。
**期望**：合并为 **1 条**。

> 本文件由 team-lead 从截图逐字誊录，供复现测试直接引用。
> 包名凡标注「待核实」的，请用**未收录**的包名（或直接走无包名路径）——
> 因为 `PlatformCatalog` 里这些 App 的包名本来就是留空的，真实场景靠**关键词兜底**识别。
> ⚠️ 不要给它们编一个已收录的包名（那会走 0.95 的包名强信号，复现结果会失真）。

## 复现要报告的内容

### 每条

| 字段 | 说明 |
|---|---|
| `platformId` | 识别到的平台 |
| `confidence` | 置信度 |
| `platformSource` | AUTO / USER |
| `counterparty` | 抽出的**原始**商户串 |
| `fingerprint` | 算出的指纹（判断哪些撞了） |
| `sourceId` / `sourceRef` | 来源 |

### 去重

- 最终分成**几组**、每组主记录是谁
- **其余每条为什么没被合并**：Tier-1 没命中？Tier-2 没生成候选？还是被护栏 REJECT / REVIEW 拦下？

### 改后

- 需求 1 + 2 落地后，这 4 条**最终合并成几条**（用户最关心的验收点）
