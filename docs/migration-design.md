# 手机换机数据迁移功能设计

> 目标：新旧手机通过各自 App 完成**无感数据迁移**，用户操作尽量少。
> 复用点：本工程已有 `BackupManager`（版本化信封 + 可选口令加密导出/导入），迁移功能是它的"设备直连"载体。

## 一、技术方案选型

| 维度 | 蓝牙（RFCOMM） | Wi-Fi Direct（P2P） | Wi-Fi 热点直连（LocalOnlyHotspot + Socket） |
|---|---|---|---|
| 传输速度 | ~25–50 KB/s（BT4/5 SPP 实测量级） | 数 MB/s~数十 MB/s | 数 MB/s~数十 MB/s |
| 配对体验 | 需设备发现 + 配对码，易失败 | 需系统"接受连接"弹窗，OEM 实现参差 | **扫码即配对**，无需输码 |
| 稳定性 | 大文件易断 | 广播发现/组主协商在部分 ROM 有 bug | 走成熟 TCP，可控性最好 |
| 无需路由器/互联网 | 是 | 是 | 是 |
| API 成熟度 | 稳定 | `WifiP2pManager` 接口陈旧、坑多 | `LocalOnlyHotspot`(API26+) 稳定，恰好覆盖本项目 minSdk 26 |

**推荐：Wi-Fi 热点直连（`LocalOnlyHotspot` + TCP Socket）为主方案，蓝牙作为最终降级兜底。**

理由：
1. 本 App 数据是**小体积本地账本**（一年流水 ≈ 1–3 MB JSON），瓶颈不在速度而在**操作的简单与可靠性**——"扫码一下"比蓝牙配对、比 Wi-Fi Direct 的确认弹窗都省事。
2. `LocalOnlyHotspot` 让旧手机**免手动开热点**（系统静默返回 SSID/口令给 App），新手机扫二维码即可拿到连接信息，把"发现设备 + 配对"压缩成一次扫码。
3. 走标准 TCP Socket，跨机型一致性远好于 `WifiP2pManager`（该接口陈旧、多厂商 bug）。
4. Wi-Fi Direct 作为"备选"保留说明：若目标机型对热点受限，可切换 `WifiP2pManager`，但**不作为默认**。
5. 蓝牙只用于**极小数据 + 双端均无 Wi-Fi 能力**的极端兜底，且会显著变慢，故排在最后。

## 二、完整流程与交互设计

```
旧手机                                   新手机
 ── ① 生成迁移二维码 ────────────────►
    （含 SSID/口令/一次性 token）          ② 扫一扫
                                         ③ 自动连热点 + token 鉴权
 ── ④ 分块推送加密备份（断点续传）──────►
                                         ⑤ SHA-256 + 条数校验
                                         ⑥ 原子落库，进入首页
```

1. **设备发现（用二维码代替广播）**：旧手机把"热点 SSID + 口令 + 一次性 token + 端口"编码进二维码；新手机扫码即锁定目标设备，**省去"搜索附近设备 → 选设备"两步**。
2. **配对（扫码 + token）**：二维码里的 token 一次性、30 秒有效，作为连接鉴权；新手机连上热点后用 token 握手，防重放。
3. **传输（分块 + 序号）**：备份 JSON（复用 `BackupManager` 的版本化信封，可按口令加密）切成 64 KB 块，逐块带序号传输；新手机逐块落临时文件。
4. **校验（双层）**：整体 SHA-256 一致性 + 块序号/长度完整性 + 最终"条数比对"（新手机显示"已迁移 N 笔流水、M 个分类"），用户一眼确认。

## 三、需要迁移的数据类型

| 数据 | 位置 | 是否迁移 | 说明 |
|---|---|---|---|
| 流水 / 分类 / 账户 / 分类规则 | Room（`BackupManager` 导出） | ✅ | 迁移主体 |
| 时薪参数 / 自由基金目标 | 当前 SharedPreferences | ⚠️ 需先做 W5（设置入库） | 未入库前**无法随备份迁移**，是本功能的依赖项 |
| 学习规则（learned） | `classifier_rules` | ✅ | 已在备份 rules 段 |
| Keystore 主密钥 | 系统密钥容器 | ❌ | 跨设备不可迁移，新机重新生成密钥包裹新口令 |
| 云同步发件箱 | `sync_outbox` | ❌ | 本地临时，不迁 |

## 四、传输安全 / 断点续传 / 重试 / 异常

- **安全**：传输内容**应用层加密**——复用 `exportEncrypted`（PBKDF2 派生 + AES-GCM），口令由用户在新手机输入一次（或旧手机显示），链路即便被旁路也是密文；配对 token 一次性 + 短时效防重放；不做裸明文 socket 传输。
- **断点续传**：分块 + 新手机持久化"已收块位图"，连接中断重连后只拉缺块。
- **失败重试**：单块失败指数退避重试（上限 3 次）；整体超时给"重试/放弃"。
- **异常兜底**：热点启动失败 → 自动降级蓝牙（若数据 < 阈值）或提示改用"导出文件 + 二维码转移码"；扫码失败 → 允许手动输 6 位配对码；中途断电 → 临时文件不生效，下次重来。
- **原子提交**：全部块校验通过后才把临时文件替换为正式库；校验失败绝不落库，避免半截数据污染。

## 五、让用户"无感"的实现要点

1. **一步到位**：扫码 = 发现 + 配对 + 连接，全程无输入（加密口令可选"跳过"或显示式）。
2. **免手动开热点**：`LocalOnlyHotspot` 由 App 静默拉起，用户不进系统设置。
3. **进度极简**：一个进度条 + "已迁移 X/Y"，不做多余步骤页。
4. **默认全自动**：失败才需要用户介入；成功直接进首页，旧手机默认不自动清数据（给用户反悔余地）。
5. **迁移后自检**：新手机首页自动跑一次"数据完整性提示"，让用户确信迁移成功。

## 六、对现有代码的依赖与新增点

- **依赖**：W5（设置入库并入备份）——否则时薪/目标迁不过去。
- **新增模块**：建议 `feature:transfer`（`DeviceTransferServer/Client`、`TransferCodec`、`QRTransferCode`），复用 `core:backup` 的导出/导入；`core:model` 增加传输协议契约，保持分层。
- **权限**：`LocalOnlyHotspot` 需 `CHANGE_WIFI_STATE`/`ACCESS_FINE_LOCATION`(Android 12 前热点/Wi-Fi 相关)；扫码需相机权限（走系统扫码或 CameraX）。
